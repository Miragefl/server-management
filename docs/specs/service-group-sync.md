# 服务组同步（service-group-sync）

## 目标
批量添加到多台服务器的同构服务（如 yd-vm121/122/123 的 kafka）支持一处编辑、可选同步全组，免除逐台修改。

## 约束
- 技术栈不变：SwiftUI + JSON 存储，macOS 14+，无第三方依赖
- 旧数据不迁移：现有 data.json 可整体清理（用户确认），groupID 直接上线
- 单台特殊配置（如某台端口不同）仍可保留——同步是显式选择，不是强制

## 模块拆解
- 数据模型：`Service` 增加 `groupID: UUID?`（软关联，可选）
- Store：批量添加时共享同一 groupID；新增「同步更新到同组」能力
- 编辑表单：保存时若属服务组，弹选择「仅本条 / 同步全组（N 台）」
- 详情页：服务行展示组标识（如「组 · 3 台」角标），编辑入口不变

## 数据模型
- `Service` 新增：`groupID: UUID?`（nil = 不成组，旧数据默认 nil 天然兼容）
- 同步语义：只同步业务字段（name / envs / port / installMethod / remark），`serverID` 各归其主、`id` / `createdAt` 不动
- 设计遵循：../doc/DB-DESIGN.md（本项目无 DB，按 JSON 模型演进约定：新增字段必须 decodeIfPresent + 默认值）

## 关键决策
- 软关联 groupID 而非独立 ServiceGroup 表：组只是同步线索，无独立属性（组名可由服务名推导），避免过度建模
- 同步走显式确认弹窗而非自动：防误覆盖单台特殊配置
- 删除保持单条独立：首版不做「整组删除」，需要时逐台删或后续加
- 手动逐台添加的服务不成组：只有批量添加才产生组，保持来源清晰

## 风险
- 同步覆盖单台差异：确认弹窗明示影响台数，且保留「仅本条」选项
- 组内服务被逐台删光后 groupID 成孤儿：无害（无人引用），不清理
- 用户想给已存在的独立服务编组：首版不支持，记录为后续诉求
